# GM Tools Hub payments backend

Serverless API for the checkout on https://gmtoolshub.com (Cloudflare Worker + D1 database + R2 private file storage). It lives in the same repository as the site and is deployed separately, because GitHub Pages can only serve static files.

## 1. What the audit found (existing site)
| Item | Finding |
|---|---|
| Frontend | Hand-written static HTML, CSS and vanilla JavaScript (no framework). Pages are generated by scripts in `build/`. |
| Hosting | GitHub Pages, custom domain gmtoolshub.com, branch `main`. Static only. |
| Backend / database / auth | None. Newsletter goes to Buttondown; enquiries open the visitor's own email or WhatsApp. |
| Ordering today | Shop cards link to WhatsApp or email; payment and delivery are manual. |
| Consequence | Real payments need a server. Browser-only "payment" code can be bypassed and must never decide that an order is paid. |

## 2. Architecture
```
Browser (gmtoolshub.com, static)                 api.gmtoolshub.com (Cloudflare Worker)
  /checkout/, /checkout/status/  --HTTPS/JSON-->   /api/products, /api/coupons/validate, /api/orders ...
  /admin-payments/ (admin console) --cookie+CSRF-> /api/admin/*          D1: orders, payments, settings, admins, audit
                                                   /api/webhooks/gateway  R2: receipt files (private)
```
- Prices are always recomputed on the server from the `products` and `coupons` tables. Client-sent prices are ignored.
- Merchant bank details are stored in the database (`settings`) and edited in the admin console. They are not in any website file.
- Orders are paid only by (a) an administrator approving a receipt after confirming the money in the bank, with the amount checked against the order total, or (b) a correctly signed gateway webhook whose amount and currency match. A screenshot upload alone never marks an order paid.
- The customer keeps a private order key (shown once, placed in the URL fragment so it is not sent to servers). Only its hash is stored.

## 3. API summary
Public: `GET /api/health`, `GET /api/config`, `GET /api/products`, `POST /api/coupons/validate`, `POST /api/orders`, `GET /api/orders/:ref` (header `X-Order-Token`), `POST /api/orders/:ref/receipt` (multipart), `POST /api/orders/:ref/cancel`, `POST /api/webhooks/gateway`.
Admin (session cookie, CSRF header on writes, roles `owner`, `finance`, `viewer`): login, logout, me, dashboard, orders (search, filter, detail), receipt view, payment approve/reject, refund record (owner), settings (owner), products and coupons (owner), CSV export (owner, finance), audit log (owner, finance).

## 4. Database
`migrations/0001_init.sql` creates: settings, products, coupons, orders, payments, webhook_events (idempotency), admins, sessions, audit_log, rate_limits. Money is stored as integer paisa.
`seed/products.sql` is generated from the shop page (`node build/make-product-seed.mjs`). Review prices before importing.

## 5. Configuration
Copy `.dev.vars.example` to `.dev.vars` for local work (never commit it). In production use `npx wrangler secret put NAME`.
| Name | Where | Purpose |
|---|---|---|
| `ALLOWED_ORIGINS` | `wrangler.toml` var | Sites allowed to call the API with cookies, comma separated. |
| `COOKIE_SAMESITE` | var | `Strict` when the API is on a subdomain of the site (recommended: `api.gmtoolshub.com`). |
| `ADMIN_SETUP_TOKEN` | secret | One-time token to create the first owner. Delete it afterwards. |
| `RESEND_API_KEY`, `MAIL_FROM` | secrets (optional) | Order emails through Resend. Without them no emails are sent. |
| `GATEWAY_API_KEY`, `GATEWAY_NAME`, `GATEWAY_WEBHOOK_SECRET` | secrets/var | Card gateway. See section 7. |
| `WALLET_API_KEY` | secret | Mobile wallet merchant API. See section 7. |
Merchant bank details, support email and order hold time are entered in the admin console, not in files.

## 6. Deployment (needs your Cloudflare account)
1. `cd backend && npm install`
2. `npx wrangler login`
3. `npx wrangler d1 create gm-payments` and put the printed `database_id` into `wrangler.toml`.
4. `npx wrangler d1 migrations apply gm-payments --remote`
5. `npx wrangler d1 execute gm-payments --remote --file seed/products.sql` (after reviewing the prices)
6. `npx wrangler r2 bucket create gm-receipts`
7. `npx wrangler secret put ADMIN_SETUP_TOKEN` (any long random value)
8. `npx wrangler deploy`, then attach the custom domain `api.gmtoolshub.com` to the Worker in the Cloudflare dashboard.
9. Create the first owner (12+ character password):
   `curl -X POST https://api.gmtoolshub.com/api/admin/setup -H "Content-Type: application/json" -d "{\"token\":\"<token>\",\"email\":\"you@example.com\",\"password\":\"<long password>\"}"`
   then `npx wrangler secret delete ADMIN_SETUP_TOKEN`.
10. Open https://gmtoolshub.com/admin-payments/, sign in, enter your real bank details under Payment settings, review Products and coupons.
11. Set `apiBase: "https://api.gmtoolshub.com"` in `assets/js/checkout-config.js`, then `node build/add-checkout-buttons.mjs`, `python build/bump.py D:/GM_Claude`, commit and push.
12. Place one small real order yourself and approve it end to end before announcing checkout.
Cloudflare Workers limit PBKDF2 to 100,000 iterations, which is what this code uses.

## 7. Card gateway and mobile wallet: what is NOT done
No card or wallet provider is connected, because that needs your own merchant account. The checkout shows them as "Not available yet" and the server refuses them. Nothing is simulated.
You need to obtain, from the provider you choose (availability depends on your country and business registration; examples to investigate, not endorsements: Pakistani gateways such as Safepay or PayFast, or the official JazzCash and Easypaisa merchant APIs): an approved merchant account, API keys, a webhook signing secret, and the provider's documentation for hosted checkout.
Then a developer must add a provider adapter that (1) creates a hosted-checkout session from an existing order total and returns its URL, and (2) maps the provider's webhook to the generic event the server already verifies: `{event_id, type: payment.succeeded|payment.failed, order_ref, amount_minor, currency, provider_ref}` signed with HMAC-SHA256 in `X-Signature`. Replace the signature check in `webhook()` with the provider's exact scheme. Never store card numbers; use the hosted page or tokenised fields.
Wallets and cards can be turned on in the admin console only when the matching secret exists on the server.

## 8. Subscriptions
Products can be one-time, monthly or annual, with an optional trial. Checkout shows the amount due today, trial length, renewal date and recurring amount before the customer confirms, requires an unticked consent box for subscriptions, and never charges automatically. With bank transfer, renewals are new orders (you remind the customer). True automatic renewals need a card gateway with recurring billing, which is not built.

## 9. Testing
`npm test` runs `test/e2e.mjs` (58 checks). `node test/dev-server.mjs` serves the site and the API together for manual browser testing with throw-away data (admin owner@test.local / ui-test-password-123, test only). See `TEST-REPORT.md` and `SECURITY-CHECKLIST.md`.

## 10. Known limits
- Tests run the real Worker code with SQLite (`node:sqlite`) and an in-memory file store, because the Cloudflare local runtime could not start on the build machine. Run `npx wrangler dev` and a deployed smoke test before going live.
- Order emails are implemented through Resend but have not been tested against Resend.
- No PCI DSS claim is made. Card data is never handled by this code.
- Revenue figures use order totals in PKR only.
