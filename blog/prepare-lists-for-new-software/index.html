Preparing Product and Customer Lists for New Software

Prepare customer and product lists before moving to new software: field rules, codes, spaces, duplicates, a trial import and checks, with a practice file.

By Gmd Khan Niazi (Ghulam Mohiuddin Khan Niazi)Published 27 November 20265 min read

New billing, stock or accounting software usually starts with your old lists. If two customers share a code, or product codes lose a digit on the way, you may only notice after people have started using the new system. Preparing the lists first gives you a chance to find these problems while the old records are still your working copy.

This guide is about getting a list ready to import. For measuring data quality across your business, see start with data quality.

Download the practice file

Excel file with made-up data. No sign-up.

1. Get the new system’s rules first

Ask the supplier for the import template and these details before cleaning anything:

  • required and optional fields;
  • the format, length and allowed values for each field;
  • which field must be unique;
  • the accepted file type and text encoding, especially for Urdu or other non-Latin text;
  • whether an import adds records, updates them or can overwrite them;
  • how a failed or wrong import can be undone.

2. Decide what to move

Do not move everything by habit. Agree which records are active, which should be kept only in an archive, and any legal or company rules about keeping them. Personal details you do not need should not go into the new system. Opening balances and stock quantities are separate work: agree the cut-off and who signs them off.

3. Protect codes before you clean

A code such as 00103 is a label, not a quantity. Excel can remove its leading zeros, and Microsoft notes that changing the format afterwards does not bring removed zeros back. Format the column as text before entering data, or set the column type to Text when importing. If zeros are already gone, restore them from the original source. Pad a code with zeros only when you know its exact fixed length and have confirmed the match.

4. Find the problems

In the practice file, the imaginary rules are: a unique five-digit customer code, a required name, an area from the agreed list, and an optional 11-digit phone number.

5. Clean in new columns

On the Old list sheet, leave the original columns unchanged and put these formulas in row 2 of empty columns. Copy them down to row 11.

Name without extra or non-breaking spaces. TRIM alone does not remove the non-breaking space, so it is replaced first:

=TRIM(SUBSTITUTE(B2,CHAR(160)," "))

Code check for five digits and one-time use:

=IF(NOT(AND(LEN(A2)=5,ISNUMBER(--A2))),"Check format",IF(COUNTIF($A$2:$A$11,A2)>1,"Used twice",""))

Area on the agreed list. This match ignores capital letters, so apply the agreed spelling in your clean copy:

=IF(ISNUMBER(MATCH(C2,'Allowed areas'!$A$2:$A$4,0)),"","Not on list")

Phone, if given, has 11 characters. This checks length only, not whether the number is real:

=IF(D2="","",IF(LEN(D2)=11,"","Check phone"))

COUNTIF can treat codes such as 00106 and 106 as the same number. That is useful as a warning, but confirm each case yourself.

6. Keep a mapping and a question list

When old values become new ones, record them: old value, new value, reason, who approved it. This lets you explain a change later and repeat it when you do the final export. Keep unresolved records on a question list instead of guessing.

7. Run a trial import

  1. Ask the supplier for a test area, and confirm that test data cannot reach live records.
  2. Import a small sample that includes difficult cases: leading zeros, long names, special characters and an optional blank.
  3. Export the sample back from the new system and compare it field by field.
  4. Fix the rules or the data, then repeat.

8. Plan the final move

  • Agree when changes to the old list stop, or how later changes will be captured.
  • Keep the original export and confirm that your backup can be restored.
  • Compare record counts: imported plus held plus intentionally left out must equal the number you started with.
  • Check a sample of important records with the people who use them.
  • Name who approves going live and who can stop it.

For a first look, the free Spreadsheet Checker can flag missing values, possible repeated rows and some spelling differences. It does not know your new system’s rules, and does not check code formats or whether a code is used by two different records.

Frequently asked questions

Can I clean the data after importing it?

Some fields may be easy to change later and others may not, especially identifiers used by transactions. Ask the supplier before relying on later cleanup.

Should two similar customer names be merged?

Not from the names alone. Confirm with other facts and with someone who knows the customers.

How big should the trial be?

Large enough to include every kind of record and the awkward cases. A tidy sample proves little.
